# 納品サポートツール

納品作業の流れ（①対象の洗い出し → ②自社捺印 → ③取引先捺印 → ④納品コピー）を段階的に自動化するツール。

| Step | 内容                                             | 状態         |
| ---- | ------------------------------------------------ | ------------ |
| 1    | ① 対象の洗い出し、管理表、整合チェック、レポート | **実装済み** |
| 2    | ④ 納品コピー                                     | 未着手       |
| 3    | ③ Teams 経由の受け渡し                           | 未着手       |
| 4    | ② 自社捺印（半自動）                             | 未着手       |

現時点では捺印とコピーは手作業で行い、管理表のステータスを手で「済」に更新する。

## 作業手順（納品1回分）

初めて使うときは、先に「[導入・試行手順](#導入試行手順)」でツールを準備する。
各機能の詳しい説明は「[使い方（2回目以降）](#使い方2回目以降)」にある。

### 全体の流れ

```text
① 準備
   │  delivery.toml に、納品名・作業フォルダ・案件を書く
   ▼
② 判定を確かめる（任意。何も書き込まない）
   │  check-names.bat
   │  └ 想定外の判定 → ファイル名・置き場所を直して、もう一度 ②
   ▼
③ 管理表を作る
   │  collect.bat
   ▼
④ 管理表を点検する
   │  「要確認」の行を 自動・手動・除外 のどれかに直す
   │  警告シートを見て、ファイルを直すか「確認済」にする
   │  └ ファイルを直した → 管理表を作り直す（下の ④ の説明を参照）
   ▼
⑤ 作業してステータスを更新する
   │  捺印・送付・コピーを手作業で行い、管理表のステータスを「済」にする
   │  └ 納品物が増えた → collect.bat（新しいファイルだけ追記される）
   ▼
⑥ 進み具合を確かめる
   │  Excel を閉じてから report.bat
   │  └ 「判定: 未完了」 → 表示された理由を見て ④ か ⑤ に戻る
   ▼
「判定: 完了」 → 納品
```

### ① 準備（納品ごとに1回）

| 操作 | ポイント |
|---|---|
| `delivery.example.toml`（または前回の納品の `delivery.toml`）をコピーして `delivery.toml` にする | ツールのフォルダに `delivery.toml` の名前で置くと、bat をダブルクリックするだけで使える。別の名前・場所に置くときは、そのファイルを bat にドラッグ＆ドロップする |
| `name`（納品名）と `work_dir`（管理表の置き場所）を書く | `work_dir` は納品ごとに別のフォルダにする（例: `'work\2026-12'`）。前回の管理表に上書きしないため |
| `[[projects]]` に案件ごとの `name` と `root`（プロジェクトルート）を書く | パスはシングルクォートで囲む。保存時の文字コードは UTF-8 |
| 必要な案件だけ `processes`・`allow_multiple` を書く | `processes`: 対象工程を絞るとき。`allow_multiple`: 機能設計書などが正しく2つ以上あるとき（[判定ルール](#判定ルール概要)） |

### ② 判定を確かめる（任意）

`bin\check-names.bat` を実行する。管理表は作らず、各ファイルの判定と警告を画面に出すだけ。

- 確かめること: 納品するファイルが一覧にあるか。種別・工程・社内外・回数が合っているか。
- 一覧にないとき: 置き場所を確かめる。ツールが見るのは、工程フォルダ直下（ドキュメント）と `成果物\内部Rv\`・`成果物\外部Rv\`（レビュー記録表・チェックリスト）だけ。
- 直し方: ファイル名を命名規則に合わせる、正しいフォルダへ移す、古い版は `back\` へ移す。直したらもう一度実行する。

### ③ 管理表を作る

`bin\collect.bat` を実行する。`work_dir` に `納品管理表_<納品名>.xlsx` ができる。作業元のファイルは変更しない。

### ④ 管理表を点検する

管理表を Excel で開き、次の2つを片づける。

| 見るところ | すること |
|---|---|
| 管理表シートの「対象」が **要確認**（黄色）の行 | 納品するなら「自動」、納品するが例外的に人が扱うなら「手動」、納品しないなら「除外」に直す |
| 警告シートのエラー・警告 | ファイル側の誤りなら作業元を直す。問題ないと判断したものは「確認済」列を「確認済」にする（次の collect・report でも引き継がれる） |

- 作業元のファイル名や置き場所を直したときは、管理表を作り直す（まだステータスを入れていないこの段階なら作り直してよい）。
  コマンドプロンプトでツールのフォルダから `py -m nohin collect -d delivery.toml --new` を実行する。前の管理表は `_backup\` に残る。
  作り直すと「確認済」の印も消えるので、ファイルの直しを先に済ませてから「確認済」を付ける。
- ステータスを入れたあとで直したときは、`bin\collect.bat` で新しい名前の行を追記し、古い名前の行（「元ファイルなし」のエラーが出る）を「除外」にする。

### ⑤ 作業してステータスを更新する

捺印・送付・コピーは手作業で行い、終わったものから管理表のステータスを「済」にする。

- ステータスの順: 指摘展開 → 自社捺印 → 取引先送付 → 取引先捺印 → 納品コピー。順を飛ばして「済」にすると「工程順序」の警告が出る（自社捺印だけは指摘展開の前でもよい）。
- その工程が要らないファイルは、最初から「不要」になっている。
- 社内のレビュー記録表に承認印を手で押すときは、「承認印の日付」列の日付にする。
- 作業の途中で納品物が増えたら `bin\collect.bat` を実行する。新しいファイルだけが追記され、入力済みのステータスは残る。

### ⑥ 進み具合を確かめる

管理表を保存して **Excel を閉じてから** `bin\report.bat` を実行する。サマリーと警告が最新になり、画面に判定が出る。

- 「判定: 未完了」: 理由（要確認の行が残っている、未完了の行がある、未確認の警告がある）が表示されるので、④ か ⑤ に戻る。
- 「判定: 完了」: 要確認の行がなく、対象の行のステータスがすべて「済」か「不要」で、警告がすべて解消済みか「確認済」になっている。

### 試行後にフィードバックしてほしいこと（伏せ字でよい）

- 判定を間違えたファイルの名前と、正しい種別
- 「規則外」になったが、本当は納品対象のファイル
- 実態と合わない警告
- エラーで止まった場合はそのメッセージ
- ファイル数と、実行にかかったおおよその時間
- レビュー記録表を `bin\inspect.bat` で読んだ結果（見出しが見つかったか、指摘の行の分類が合っているか）
- クリップスタンプで印を押したダミーの記録表を `bin\inspect.bat` で読んだときの「画像・図形」の表示（後半の印影検出に使う。手順は `docs\様式ヒアリングシート.txt` の最後）

## 使い方（2回目以降）

### 1. 判定結果を確認する（任意・何も書き込まない）

`bin\check-names.bat` を実行する（`delivery.toml` をドラッグ＆ドロップしてもよい）。
各ファイルがどの種別と判定されるか、警告が出るかを画面で確認できる。命名規則（`config.toml`）を変えたときの確認にも使う。

### 2. 管理表を作る

`bin\collect.bat` を実行すると、`delivery.toml` の `work_dir` に `納品管理表_<納品名>.xlsx` ができる。

- 作業元のファイルは読むだけで、変更しない。
- 2回目以降に実行すると、既存の管理表に**新しく見つかったファイルだけを追記**する（手で直した内容は残る）。更新前の管理表は `work_dir\_backup\` に退避される。
- 作り直したいときは `python -m nohin collect -d delivery.toml --new`（以前の管理表は退避される）。
- 追記では、すでに管理表にある行は消さない。v0.1.0 で作った管理表には、今は拾わない場所（`作業用\` など）の行が残っているので、`--new` で作り直すか、その行を「除外」にする。

### 3. 管理表を確認・更新する

| シート   | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| サマリー | 件数、工程別ステータス、案件・工程別の進み具合、完了判定     |
| 管理表   | 1行が1ファイル。人が直すのは「対象」「各ステータス」「備考」 |
| 警告     | 漏れ・不整合の一覧。問題ないと判断したものは「確認済」にする |

- **対象**: 自動 / 手動（例外。人が対応する）/ 除外（納品しない）/ 要確認（ツールが判断できなかった。どれかに直す）
- **ステータス**: 未 / 済 / NG / 不要（その工程が要らないファイル）
- 元パス・納品先などの詳細列は折りたたんである。列見出しの上の「＋」ボタンで表示できる。
- **指摘展開**: 社外レビュー記録表を、指摘を書いた時点で取引先に展開したか（1回目の展開）。社外レビュー記録表以外は「不要」。
  自社捺印は指摘展開の前後どちらで済にしてもよい。取引先送付以降を済にするときは、指摘展開も済にしておく。

### レビュー記録表の進捗（collect・report のたびに中身を読み直す）

レビュー記録表は、中身を読み取り専用で調べて、管理表の次の列に書き出す。ステータスへの自動反映はしないので、ステータスは人が更新する。

| 列 | 内容 |
|---|---|
| 記録表の状況 | 処置完了 / 処置中 / 指摘なし / 表なし / 読取不可 |
| 指摘の進捗 | 例: `指摘3（捺印不要1）・処置2・日付2` |
| 承認印の日付 | 社内のレビュー記録表で、処置の日付のうち最も新しい日。承認印を手で押すときはこの日付にする |

- 指摘の表は、見出しの文字（指摘事項・処置欄・日付・捺印(自社) など）で探す。上部の行が増えて表がずれても追従する。見出しの文字は `config.toml` の `[review_table]` で変えられる。
- 処置の日付は、処置欄より右で最も近い「日付」の列。
- 捺印欄に「-」（全角・半角どちらでも）がある行は「捺印不要」。処置欄・日付が空でも未完了にならない。
- 指摘事項が「指摘なし」「以下余白」の行は指摘として数えない。図形で行を隠す場合は、**隠した行に指摘の文字を残さない**こと（残っていると指摘として数える）。
- 承認欄は、指摘の表より上の「承認」の下のセル。
- 主な警告: 処置欄があるのに日付がない（日付なし）、指摘事項が空の行に記入がある、指摘の表が見つからない、承認欄が見つからない、ファイルを読めない。
- 1つのファイルの読み取り結果を詳しく見るには `bin\inspect.bat` にドラッグ＆ドロップする（読み取り専用）。

### 4. 進捗・完了を確認する

`bin\report.bat` を実行すると、サマリーと警告を最新の状態に更新する。
次の条件をすべて満たすと「完了」と判定される。

- 「要確認」の行がない
- 対象（自動・手動）の行のステータスがすべて「済」か「不要」
- エラー・警告がすべて解消済みか「確認済」

> 管理表を Excel で開いたまま実行すると、書き込まずに停止する。閉じてから実行する。

## 判定ルール（概要）

- 工程フォルダ（`030.調査` など）の直下 → ドキュメント
- `成果物\内部Rv\`・`成果物\外部Rv\`（日付フォルダ `yyyymmdd\` の中も含む）→ レビュー記録表・チェックリスト
  - ここにドキュメントと同じ名前のファイル（レビューに使った写しなど）があっても、管理表には載せない。
- 上の2か所以外（`作業用\` などのフォルダ、`back\`、内部Rv/外部Rv の下の日付でないフォルダ）は見ない。管理表にも載らない。
  Excel の一時ファイル（`~$`）は無視する。
- 同じ工程に同じ種類のドキュメントが2つ以上あると「ドキュメント重複」のエラーになる。
  案件によって正しく複数ある場合（機能設計書が機能ごとに分かれているなど）は、`delivery.toml` のその案件に
  `allow_multiple = ["機能設計書"]` と書くと、その案件ではそのドキュメントの重複を警告しない。名前は `config.toml` の `[[documents]]` の `name` で書く。
- 命名規則に当てはまらないファイルは「除外」として一覧に載せる（警告シートに「情報」として記載）。
  ただし、納品物の置き場所（工程直下・内部Rv/外部Rv）にある Excel は名前の誤りの可能性があるため「要確認」にする。
- 括弧の全角・半角は区別しない。
- 命名規則や工程の対応表は `config.toml` で変更できる。

```sh
python -m unittest discover -s tests -t .     # テスト
python -m tests.dummy demo                    # demo/ にダミーの3案件を作る
python -m nohin collect -d demo/delivery.toml
python -m tests.verify_demo                   # 正誤表と実際の出力を突き合わせる（○/×）
python -m nohin inspect <レビュー記録表.xlsx>   # 記録表1つの読み取り結果を表示する
python -m tests.verify_demo demo --markdown docs/デモ正誤表.md   # 正誤表を再生成する
```

ダミーに仕込む内容を変えたときは、`tests/dummy.py` と `tests/verify_demo.py` の CASES・EXPECTED_ISSUES・EXPECTED_TOTALS を合わせて直し、正誤表を再生成する（古いままだとテストが失敗する）。
