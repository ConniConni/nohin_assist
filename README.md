# 納品サポートツール

納品作業の流れ（①対象の洗い出し → ②自社捺印 → ③取引先捺印 → ④納品コピー）を段階的に自動化するツール。

| Step | 内容                                             | 状態         |
| ---- | ------------------------------------------------ | ------------ |
| 1    | ① 対象の洗い出し、管理表、整合チェック、レポート | **実装済み** |
| 2    | ④ 納品コピー                                     | **実装済み** |
| 3    | ③ Teams 経由の受け渡し                           | 未着手       |
| 4    | ② 自社捺印（半自動）                             | 未着手       |

現時点では、捺印と取引先とのやり取りは手作業で行い、管理表のステータスを手で「済」に更新する。
前の工程が済んだ行の納品コピーは、`deliver` で自動で行える。

## 導入・試行手順

ダミーデータで動作を確認してから、実際の案件で試す。手順 1〜4 は初回のみ。
コマンドは、ツールを展開したフォルダでコマンドプロンプトを開いて実行する。
`py` が見つからない場合は、`py` を `python` に置き換える。

### 試行後にフィードバックしてほしいこと（伏せ字でよい）

- 判定を間違えたファイルの名前と、正しい種別
- 「規則外」になったが、本当は納品対象のファイル
- 実態と合わない警告
- エラーで止まった場合はそのメッセージ
- ファイル数と、実行にかかったおおよその時間
- レビュー記録表を `bin\inspect.bat` で読んだ結果（見出しが見つかったか、指摘の行の分類が合っているか）
- クリップスタンプで印を押したダミーの記録表を `bin\inspect.bat` で読んだときの「画像・図形」の表示（後半の印影検出に使う。手順は `docs\様式ヒアリングシート.txt` の最後）
- 納品コピーの「処理時間」と「合計 … MB」の表示（共有フォルダの場合）。エラーで止まった・NG になった場合は `<work_dir>\_log\` のログ

### うまくいかないとき

| 症状                                                               | 対処                                                                                                             |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| `'py' は、内部コマンドまたは外部コマンド…として認識されていません` | `py` を `python` に置き換える。bat ファイルは自動で切り替わる                                                    |
| `config.toml が見つかりません`                                     | ツールのフォルダか、`delivery.toml` と同じ場所に `config.toml` を置く                                            |
| `プロジェクトルートが見つかりません`                               | `delivery.toml` の `root` のパスと、シングルクォートで囲んでいるかを確認する                                     |
| `管理表が Excel で開かれています`                                  | 管理表を閉じてから再実行する                                                                                     |
| `管理表の見出しが足りません`                                       | 管理表の列名を変えたり列を消したりしていないか確認する。直せない場合は `_backup\` から戻すか、`--new` で作り直す |
| 日本語が文字化けする                                               | `delivery.toml` を UTF-8 で保存し直す（メモ帳の「名前を付けて保存」で文字コードを選べる）                        |
| `dest_root（納品先のフォルダ）を書いてください`                    | `delivery.toml` の `[delivery]` に `dest_root = '…'` を書く                                                     |
| 納品コピーが NG になった                                           | `<work_dir>\_log\` のログで理由を確かめる（ファイルが開かれている、パスが長すぎる など）。直してから再実行する   |
| report が遅い（納品先が共有フォルダ）                              | `config.toml` の `[deliver]` で `verify_hash_on_report = false` にする（ファイルがあるかとサイズだけを確かめる） |

## 使い方（2回目以降）

### 1. 判定結果を確認する（任意・何も書き込まない）

`bin\check-names.bat` を実行する（`delivery.toml` をドラッグ＆ドロップしてもよい）。
各ファイルがどの種別と判定されるか、警告が出るかを画面で確認できる。命名規則（`config.toml`）を変えたときの確認にも使う。

### 2. 管理表を作る

`bin\collect.bat` を実行すると、`delivery.toml` の `work_dir` に `納品管理表_<納品名>.xlsx` ができる。

- 作業元のファイルは読むだけで、変更しない。
- 2回目以降に実行すると、既存の管理表に**新しく見つかったファイルだけを追記**する（手で直した内容は残る）。更新前の管理表は `work_dir\_backup\` に退避される。
- 作り直したいときは `python -m nohin collect -d delivery.toml --new`（以前の管理表は退避される）。

### 3. 管理表を確認・更新する

| シート   | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| サマリー | 件数、工程別ステータス、案件・工程別の進み具合、完了判定     |
| 管理表   | 1行が1ファイル。人が直すのは「対象」「各ステータス」「備考」 |
| 警告     | 漏れ・不整合の一覧。問題ないと判断したものは「確認済」にする |

- **対象**: 自動 / 手動（例外。人が対応する）/ 除外（納品しない）/ 要確認（ツールが判断できなかった。どれかに直す）
- **ステータス**: 未 / 済 / NG / 不要（その工程が要らないファイル）
- 元パス・納品先などの詳細列は折りたたんである。列見出しの上の「＋」ボタンで表示できる。
- **指摘展開**: 社外レビュー記録表を、指摘を書いた時点で取引先に展開したか（1回目の展開）。社外レビュー記録表以外は「不要」。
  自社捺印は指摘展開の前後どちらで済にしてもよい。取引先送付以降を済にするときは、指摘展開も済にしておく。

### レビュー記録表の進捗（collect・report のたびに中身を読み直す）

レビュー記録表は、中身を読み取り専用で調べて、管理表の次の列に書き出す。ステータスへの自動反映はしないので、ステータスは人が更新する。

| 列 | 内容 |
|---|---|
| 記録表の状況 | 処置完了 / 処置中 / 指摘なし / 表なし / 読取不可 |
| 指摘の進捗 | 例: `指摘3（捺印不要1）・処置2・日付2` |
| 承認印の日付 | 社内のレビュー記録表で、処置の日付のうち最も新しい日。承認印を手で押すときはこの日付にする |

- 指摘の表は、見出しの文字（指摘事項・処置欄・日付・捺印(自社) など）で探す。上部の行が増えて表がずれても追従する。見出しの文字は `config.toml` の `[review_table]` で変えられる。
- 処置の日付は、処置欄より右で最も近い「日付」の列。
- 捺印欄に「-」（全角・半角どちらでも）がある行は「捺印不要」。処置欄・日付が空でも未完了にならない。
- 指摘事項が「指摘なし」「以下余白」の行は指摘として数えない。図形で行を隠す場合は、**隠した行に指摘の文字を残さない**こと（残っていると指摘として数える）。
- 承認欄は、指摘の表より上の「承認」の下のセル。
- 主な警告: 処置欄があるのに日付がない（日付なし）、指摘事項が空の行に記入がある、指摘の表が見つからない、承認欄が見つからない、ファイルを読めない。
- 1つのファイルの読み取り結果を詳しく見るには `bin\inspect.bat` にドラッグ＆ドロップする（読み取り専用）。

### 4. 納品先にコピーする（納品コピー）

`delivery.toml` の `dest_root` に書いた納品先へ、`<案件>\<工程フォルダ>\`（ドキュメント）と `<工程フォルダ>\成果物\`（レビュー記録表・チェックリスト）の構成でコピーする。
コピー先は管理表の「納品先(相対)」列（詳細列）。作業元の原本は読むだけで、変更しない。

| bat | モード | 動き |
|---|---|---|
| `bin\deliver.bat` | list | 対象と飛ばす行の一覧を出すだけ。何も変更しない（管理表も書き換えない） |
| `bin\deliver-check.bat` | check | 納品先に同じ名前で**内容の違う**ファイルが1件でもあれば、1件もコピーせずに止める。なければコピーする |
| `bin\deliver-overwrite.bat` | overwrite | 内容の違う既存ファイルを `_backup` に退避してから上書きする（実行前に y/N を聞く） |

- **コピーする行**: 「対象」が「自動」で、前の工程（指摘展開・自社捺印・取引先送付・取引先捺印）がすべて「済」か「不要」の行。
- 納品先に**同じ内容**のファイルがすでにあれば、コピーせずに「済」にする。
- コピーのあと、ハッシュ（SHA-256）で原本と照合し、一致すれば「納品コピー」を「済」にして日時とハッシュを書く。失敗した行は「NG」になる（理由はログに出る）。
- 一時ファイル（`～.nohin-tmp`）に書いてから置き換えるので、途中で止まっても納品先に壊れたファイルは残らない。
- 次の行は飛ばす（一覧に理由が出る）: 要確認・除外の行、前の工程が未の行、「納品先衝突」「元ファイルなし」のエラーがある行、原本が Excel で開かれている行、納品先(相対)が空か案件のフォルダの外を指す行。
- check・overwrite・restore の画面の内容は `<work_dir>\_log\` にも保存される。

**「自動」と「手動」の違い**

| 対象 | 意味 |
|---|---|
| 自動 | ツールがコピーする。判定を直しただけで、普通にコピーしてよい行もこちら（「納品先(相対)」が必要） |
| 手動 | 人が手で配置する。ツールはコピーしないが、`deliver` の一覧に納品先の状態（なし／同じ内容／内容が違う）を出す |

- 命名規則外のファイルは「納品先(相対)」が空になっている。納品する場合は人が入力する。`deliver` の一覧に**候補**が出るので参考にする。
- 手で置いて「納品コピー」を「済」にすると、report で原本と中身を比べ、違えば「手動配置の内容違い」の警告を出す。
- 管理表にないファイル（`back\` の中のものなど）を手で納品した場合は、「管理表にないファイル」の警告を警告シートで「確認済」にする。
- 注意: `collect --new` で作り直すと、手で直した「対象」や「納品先(相対)」も消える（退避された管理表から戻す）。手で入力した納品先(相対)が構成として正しいかは、ツールでは確かめない。

**納品先のチェック**（`dest_root` を書いていれば collect・report・deliver のたびに行う）

| 種類 | 内容 |
|---|---|
| 管理表にないファイル | 納品先にあるのに、どの行の納品先(相対)でもない |
| 納品先なし | 「納品コピー」が済なのに、納品先にない |
| 納品先の内容違い | 納品先のファイルが、納品コピーしたときと違う |
| 納品後に原本が更新 | 納品コピーのあとに原本が変わった（overwrite で置き直す） |
| 手動配置の内容違い | 手で置いたファイルが原本と違う |
| 一時ファイルの残り | 途中で止まったコピーの一時ファイルが残っている（消す） |
| 納品先が不正・パス長 | 納品先(相対)が案件のフォルダの外を指している／納品先のパスが260文字以上 |

- report が遅い場合（納品先が共有フォルダなど）は、`config.toml` の `[deliver]` で `verify_hash_on_report = false` にすると、ハッシュの代わりにファイルがあるかとサイズだけを確かめる。

**バックアップと元に戻す（restore）**

- overwrite で上書きする直前の納品先のファイルを `<work_dir>\_backup\<日時>_納品コピー\` に、納品先と同じ相対パスで退避し、管理表の「バックアップ先」（詳細列）に記録する。書き込む前の管理表も同じフォルダに退避する。
- `bin\restore.bat` を実行して管理表の No を入力すると（例: `12 15`）、その行の納品先をバックアップの内容に戻し、「納品コピー」を「未」に戻す。戻す前の納品先のファイルは `_backup\<日時>_restore\` に退避する。
- 戻せるのは、その行の直前の1回だけ（管理表に残るのは最新のバックアップ）。古いバックアップは `_backup` に残っているので、必要なら手でコピーする。
- 新規でコピーした行（上書きしていない行）は戻せない。間違えて置いた場合は、納品先のファイルを手で消して「納品コピー」を「未」に戻す。
- バックアップは自動では消さない。サマリーシートに件数と合計サイズが出るので、納品が終わったら `_backup` を手で消す。

### 5. 進捗・完了を確認する

`bin\report.bat` を実行すると、サマリーと警告を最新の状態に更新する。
次の条件をすべて満たすと「完了」と判定される。

- 「要確認」の行がない
- 対象（自動・手動）の行のステータスがすべて「済」か「不要」
- エラー・警告がすべて解消済みか「確認済」

> 管理表を Excel で開いたまま実行すると、書き込まずに停止する。閉じてから実行する。

## 判定ルール（概要）

- 工程フォルダ（`030.調査` など）の直下 → ドキュメント
- `成果物\内部Rv\`・`成果物\外部Rv\`（日付フォルダ `yyyymmdd\` の中も含む）→ レビュー記録表・チェックリスト
- `back\` の下は対象外。Excel の一時ファイル（`~$`）は無視する。
- 命名規則に当てはまらないファイルは「除外」として一覧に載せる（警告シートに「情報」として記載）。
  ただし、納品物の置き場所（工程直下・内部Rv/外部Rv）にある Excel は名前の誤りの可能性があるため「要確認」にする。
- 括弧の全角・半角は区別しない。
- 命名規則や工程の対応表は `config.toml` で変更できる。

## 開発者向け

```sh
python -m unittest discover -s tests -t .     # テスト
python -m tests.dummy demo                    # demo/ にダミーの3案件を作る
python -m nohin collect -d demo/delivery.toml
python -m tests.verify_demo                   # 正誤表と実際の出力を突き合わせる（○/×）
python -m nohin deliver -d demo/delivery.toml --mode check       # 内容の違うファイルがあるので止まる
python -m nohin deliver -d demo/delivery.toml --mode overwrite
python -m tests.verify_demo --stage deliver   # 納品コピーのあとの状態を突き合わせる
python -m nohin restore -d demo/delivery.toml 11                 # No.11 を上書き前に戻す
python -m nohin inspect <レビュー記録表.xlsx>   # 記録表1つの読み取り結果を表示する
python -m tests.verify_demo demo --markdown docs/デモ正誤表.md   # 正誤表を再生成する
```

ダミーに仕込む内容を変えたときは、`tests/dummy.py` と `tests/verify_demo.py` の CASES・EXPECTED_ISSUES・EXPECTED_TOTALS・DELIVER_CASES・EXPECTED_COPIED を合わせて直し、正誤表を再生成する（古いままだとテストが失敗する）。
