# 納品サポートツール

納品作業の流れ（①対象の洗い出し → ②自社捺印 → ③取引先捺印 → ④納品コピー）を段階的に自動化するツール。

| Step | 内容                                             | 状態         |
| ---- | ------------------------------------------------ | ------------ |
| 1    | ① 対象の洗い出し、管理表、整合チェック、レポート | **実装済み** |
| 2    | ④ 納品コピー                                     | 未着手       |
| 3    | ③ Teams 経由の受け渡し                           | 未着手       |
| 4    | ② 自社捺印（半自動）                             | 未着手       |

現時点では捺印とコピーは手作業で行い、管理表のステータスを手で「済」に更新する。

## 導入・試行手順

ダミーデータで動作を確認してから、実際の案件で試す。手順 1〜4 は初回のみ。
コマンドは、ツールを展開したフォルダでコマンドプロンプトを開いて実行する。
`py` が見つからない場合は、`py` を `python` に置き換える。

### 手順 1. ツールを展開

| 操作                                        | 期待結果                                                          |
| ------------------------------------------- | ----------------------------------------------------------------- |
| 浅い階層に展開する（例: `C:\tools\nohin\`） | フォルダの中に `nohin\`、`bin\`、`tests\`、`README.md` などがある |

### 手順 2. Python とライブラリを確認する

| 操作                                    | 期待結果                                                                                                   |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `py --version`                          | `Python 3.11.x` 以上が表示される                                                                           |
| `py -m pip install -r requirements.txt` | 最後に `Successfully installed openpyxl-…`（入っている場合は `Requirement already satisfied`）と表示される |

> プロキシのエラーが出る場合は、`--proxy http://<社内プロキシ>:<ポート>` を付けて実行する。

### 手順 3. ダミーデータで動作を確認する（実データには触れない）

| 操作                                                 | 期待結果                                                                                                                                                      |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `py -m unittest discover -s tests -t .`              | 最後に `Ran 25 tests` と `OK` が表示される（テストは一時フォルダの中だけで動く）                                                                              |
| `py -m tests.dummy demo`                             | `ダミーを作成しました: …\demo` と表示され、`demo\src\` に案件A〜C ができる                                                                                    |
| `bin\collect.bat demo\delivery.toml`                 | `管理表を保存しました`、`判定: 未完了`、`全 63 行（対象 60 / 要確認 2 / 除外 1）`、`エラー 2 件 / 警告 5 件 / 情報 2 件` と表示され、エラー・警告の内訳が続く |
| `demo\work\納品管理表_デモ納品.xlsx` を Excel で開く | 「サマリー」「管理表」「警告」の3シートがある。管理表の「対象」と各ステータス列でプルダウンが選べ、「済」は緑、「要確認」は黄色になる                         |

### 手順 4. 設定ファイルを用意する

| 操作                                                                                                                                                                                                       | 期待結果                                                                                 |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `config.example.toml` をコピーして `config.toml` にする                                                                                                                                                    | 中身は変更不要                                                                           |
| `delivery.example.toml` をコピーして `delivery.toml` にし、メモ帳で `name`（納品名）、`work_dir`（管理表の置き場所）、`[[projects]]` の `name` と `root` を書く。最初は1案件だけにすると結果を確認しやすい | パスはシングルクォートで囲む（例: `root = 'C:\work\案件A'`）。保存時の文字コードは UTF-8 |

### 手順 5. 実際の案件で判定結果を確認する（読み取り専用）

| 操作                                                                                     | 期待結果                                                                                                                                                                  |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bin\check-names.bat` をダブルクリック（`delivery.toml` をドラッグ＆ドロップしてもよい） | `判定結果（管理表は作成・変更しません）` に続いて、案件ごとに「工程 / 種別 / 社内外・回数 / 対象 / パス」の一覧と警告が表示される。ファイルは何も作られず、変更もされない |

### 手順 6. 管理表を作って確認する

| 操作                                                                                       | 期待結果                                                                                                                            |
| ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| `bin\collect.bat` を実行する                                                               | `管理表を保存しました: <work_dir>\納品管理表_<納品名>.xlsx` と表示される。作業元のファイルは変更されない                            |
| 管理表を Excel で開いて確認する                                                            | 種別・工程・社内外・回数が実態と合っている。「要確認」「除外」の行と警告シートの内容が妥当である                                    |
| ステータスを何か所か「済」にして保存し、**Excel を閉じてから** `bin\report.bat` を実行する | `管理表のサマリー・警告を更新しました` と表示され、サマリーシートの件数が変わる                                                     |
| もう一度 `bin\collect.bat` を実行する                                                      | `既存の管理表に追記します（新規 0 件）` と表示され、手で直した内容が残っている。更新前の管理表が `<work_dir>\_backup\` に退避される |

### 試行後にフィードバックしてほしいこと（伏せ字でよい）

- 判定を間違えたファイルの名前と、正しい種別
- 「規則外」になったが、本当は納品対象のファイル
- 実態と合わない警告
- エラーで止まった場合はそのメッセージ
- ファイル数と、実行にかかったおおよその時間

### うまくいかないとき

| 症状                                                               | 対処                                                                                                             |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| `'py' は、内部コマンドまたは外部コマンド…として認識されていません` | `py` を `python` に置き換える。bat ファイルは自動で切り替わる                                                    |
| `config.toml が見つかりません`                                     | ツールのフォルダか、`delivery.toml` と同じ場所に `config.toml` を置く                                            |
| `プロジェクトルートが見つかりません`                               | `delivery.toml` の `root` のパスと、シングルクォートで囲んでいるかを確認する                                     |
| `管理表が Excel で開かれています`                                  | 管理表を閉じてから再実行する                                                                                     |
| `管理表の見出しが足りません`                                       | 管理表の列名を変えたり列を消したりしていないか確認する。直せない場合は `_backup\` から戻すか、`--new` で作り直す |
| 日本語が文字化けする                                               | `delivery.toml` を UTF-8 で保存し直す（メモ帳の「名前を付けて保存」で文字コードを選べる）                        |

## 使い方（2回目以降）

### 1. 判定結果を確認する（任意・何も書き込まない）

`bin\check-names.bat` を実行する（`delivery.toml` をドラッグ＆ドロップしてもよい）。
各ファイルがどの種別と判定されるか、警告が出るかを画面で確認できる。命名規則（`config.toml`）を変えたときの確認にも使う。

### 2. 管理表を作る

`bin\collect.bat` を実行すると、`delivery.toml` の `work_dir` に `納品管理表_<納品名>.xlsx` ができる。

- 作業元のファイルは読むだけで、変更しない。
- 2回目以降に実行すると、既存の管理表に**新しく見つかったファイルだけを追記**する（手で直した内容は残る）。更新前の管理表は `work_dir\_backup\` に退避される。
- 作り直したいときは `python -m nohin collect -d delivery.toml --new`（以前の管理表は退避される）。

### 3. 管理表を確認・更新する

| シート   | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| サマリー | 件数、工程別ステータス、案件・工程別の進み具合、完了判定     |
| 管理表   | 1行が1ファイル。人が直すのは「対象」「各ステータス」「備考」 |
| 警告     | 漏れ・不整合の一覧。問題ないと判断したものは「確認済」にする |

- **対象**: 自動 / 手動（例外。人が対応する）/ 除外（納品しない）/ 要確認（ツールが判断できなかった。どれかに直す）
- **ステータス**: 未 / 済 / NG / 不要（その工程が要らないファイル）
- 元パス・納品先などの詳細列は折りたたんである。列見出しの上の「＋」ボタンで表示できる。

### 4. 進捗・完了を確認する

`bin\report.bat` を実行すると、サマリーと警告を最新の状態に更新する。
次の条件をすべて満たすと「完了」と判定される。

- 「要確認」の行がない
- 対象（自動・手動）の行のステータスがすべて「済」か「不要」
- エラー・警告がすべて解消済みか「確認済」

> 管理表を Excel で開いたまま実行すると、書き込まずに停止する。閉じてから実行する。

## 判定ルール（概要）

- 工程フォルダ（`030.調査` など）の直下 → ドキュメント
- `成果物\内部Rv\`・`成果物\外部Rv\`（日付フォルダ `yyyymmdd\` の中も含む）→ レビュー記録表・チェックリスト
- `back\` の下は対象外。Excel の一時ファイル（`~$`）は無視する。
- 命名規則に当てはまらないファイルは「除外」として一覧に載せる（警告シートに「情報」として記載）。
  ただし、納品物の置き場所（工程直下・内部Rv/外部Rv）にある Excel は名前の誤りの可能性があるため「要確認」にする。
- 括弧の全角・半角は区別しない。
- 命名規則や工程の対応表は `config.toml` で変更できる。

## 開発者向け

```sh
python -m unittest discover -s tests -t .     # テスト
python -m tests.dummy demo                    # demo/ にダミーの3案件を作る
python -m nohin collect -d demo/delivery.toml
```
